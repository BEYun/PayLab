# PayLab 테스트 정착 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 형식적 테스트 6개를 단위·통합·UI 실제 테스트로 바꾸고, Claude의 `git commit` 직전에 전체 테스트를 강제하는 hook과 `CLAUDE.md` 테스트 규칙을 만든다.

**Architecture:** 이미 있는 코드에 대한 특성 테스트다. 테스트를 먼저 쓰고 통과를 확인한 뒤, 대상 코드를 잠깐 망가뜨려 테스트가 실제로 실패하는지 확인하고(돌연변이 확인) 되돌린다. 단위 테스트는 각 모듈 `Tests`(병렬), 가짜 서버 전역 등록을 쓰는 통합 테스트는 `DataKitTests`·`PayLabTests`의 `.serialized` Suite, UI 테스트는 별도 스킴 `PayLabUITests`. `scripts/test-all.sh`가 전체를 돌리고, `.claude/settings.json`의 `PreToolUse` hook이 커밋 전에 이를 실행한다.

**Tech Stack:** Xcode 27.2, Swift 6 언어 모드, Swift Testing, XCTest(UI 전용), Tuist 4.216.0, bash, jq(`/usr/bin/jq`), Claude Code hooks

**Spec:** `docs/superpowers/specs/2026-11-10-testing-design.md`

## Global Constraints

- 단위·통합: Swift Testing (`import Testing`). XCTest는 UI 테스트(`XCUIApplication`)에만.
- 외부 라이브러리 추가 금지. 스냅샷 테스트 없음.
- **제품 코드(`Modules/*/Sources`) 수정 금지.** 유일한 예외: Task 7에서 UI 쿼리가 텍스트로 안 잡힐 때 해당 요소에 `.accessibilityIdentifier` 추가. 돌연변이 확인 후에는 반드시 `git checkout -- <파일>`로 되돌리고, 커밋 전 `git diff --stat -- 'Modules/*/Sources'`가 비어 있어야 한다 (Task 7 예외 제외).
- 동작이 이상해 보여도 고치지 않는다. 현재 동작을 테스트로 고정하고 설계 부록 A에 기록한다.
- `FakeBackend.makeSession`(또는 `AppEnvironment.makeRepository`)을 부르는 테스트는 그 타깃의 `@Suite(.serialized)` 안에만 둔다. 그 밖의 테스트는 병렬.
- 테스트의 `FakeServer`는 `latency: .zero`. 예외: `AppEnvironment.makeRepository` 경유 테스트는 기본 300ms.
- UI 테스트에 고정 sleep 금지. `waitForExistence(timeout: 5)`.
- `Project.swift`: UI 테스트 타깃 1개 + 스킴 1개 추가만. 공용 `PayLab` 스킴의 테스트 구성은 그대로.
- `CLAUDE.md`: 기존 줄 수정 금지, `## 테스트` 섹션만 추가.
- 커밋 금지: `*.xcodeproj`, `*.xcworkspace`, `Derived/`, `.build/`.
- `xcode-select -p`가 Command Line Tools면 셸마다 `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.

## 확인된 사실 (2026-11-10, 계획 작성 중 실측)

- `PayLabTests`는 PayLab 앱 프로세스 안에서 돈다 (`TEST_HOST` = PayLab.app). 앱이 실행되며 `AppEnvironment.makeRepository`로 자기 가짜 서버를 먼저 등록하고, 홈 화면이 `GET /accounts`를 보낸다. 테스트가 나중에 다시 등록하면 앱의 요청도 테스트 서버로 가지만 읽기뿐이라 상태를 바꾸지 않는다.
- `DomainTests`, `DataKitTests` 등 호스트 없는 번들은 각자 다른 `xctest` 프로세스에서 돈다. → 번들 간 전역 간섭 없음.
- `PayLabTests`는 `Project.swift` 변경 없이 `import DataKit`, `Domain`, `HomeFeature`, `TransferFeature`가 된다.
- 기준 실행: 깨끗한 빌드 + 형식적 테스트 6개 = 16초.
- Claude Code hook: `.tool_input.command`에 명령, `.cwd`에 작업 폴더. 종료 코드 2만 차단, 다른 0 아닌 코드는 통과. `timeout` 단위 초, 기본 600. 시간 초과 시 기본은 **통과**. 설정 파일 수정은 실행 중인 세션에 자동 반영(파일 감시).

## 공통 명령

| 이름 | 명령 | 통과 기준 |
|---|---|---|
| **생성** | `tuist generate --no-open` | 오류 없이 종료 |
| **모듈 테스트 `<T>`** | `xcodebuild -workspace PayLab.xcworkspace -scheme PayLab -destination "platform=iOS Simulator,name=PayLab-$(git branch --show-current)" -derivedDataPath .build/DerivedData test -only-testing:<T> 2>&1 \| grep -E "✘\|✔ Test run\|error:\|TEST SUCCEEDED\|TEST FAILED"` | `** TEST SUCCEEDED **`, `✔ Test run with N tests` |
| **공용 테스트** | 위에서 `-only-testing:<T>` 제거 | 같음 |
| **UI 테스트** | `-scheme PayLabUITests`로 바꾼 같은 명령 (`-only-testing` 없음), grep에 `Executed` 추가 | `** TEST SUCCEEDED **`, `Executed 2 tests, with 0 failures` |
| **전체 테스트** (Task 8 이후) | `scripts/test-all.sh` | 종료 코드 0, 마지막 줄 `ALL TESTS PASSED` |

시뮬레이터 `PayLab-<브랜치>`는 이미 생성·부팅돼 있다. 꺼져 있으면 `xcrun simctl boot "PayLab-$(git branch --show-current)"`.

## Review Focus

1. **복합 명령 속 커밋:** `cd x && git commit -am m`, `git -C . commit` → hook이 반드시 테스트를 돌려야 한다. Task 8 `scripts/test-hook.sh` 케이스로 고정.
2. **테스트를 돌릴 수조차 없는 상황**(tuist 없음, 빌드 오류, 시뮬레이터 부팅 실패, 명령 없음) → 통과가 아니라 차단(2). Task 8 케이스 `PAYLAB_TEST_CMD=false`, `PAYLAB_TEST_CMD=/nonexistent`.
3. **hook 시간 초과** → 기본이 통과라 커밋이 새어 나간다. Task 8에서 `"timeout": 600` + `"onFailure": "block"`(문서 확인 후), 전체 실행 시간 실측이 300초 미만인지 확인.
4. **홈 잔액 갱신은 비동기**(시트 닫힘 → `load`, 300ms 지연) → UI 테스트는 대기 후 확인. 즉시 단정하면 불안정. Task 7.
5. **실행 순서·반복 의존:** 각 테스트가 자기 `FakeServer`를 새로 만들고 앞 테스트 결과에 기대지 않는다. Task 9에서 전체 3회 연속 통과로 확인.
